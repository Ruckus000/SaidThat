# Proposal and Demo Separation

## Shared foundation

Proposal and demo must share:

- requirements and claims;
- terminology;
- evidence;
- Design DNA;
- accessibility target;
- trust posture;
- content assumptions.

## Proposal purpose

Help an evaluator determine whether the response is compliant, credible, differentiated, evidence-backed, feasible, and low-risk.

Useful structures include compliance matrices, win themes, evidence diagrams, implementation timelines, risk controls, comparisons, and annotated screenshots.

## Demo purpose

Prove that representative users can complete important tasks and that the visual system is responsive, accessible, coherent, and maintainable.

Useful flows include finding a service, applying or paying, locating an event or document, searching, receiving an update, and recovering from an error.

## Anti-slop rule

Do not force proposal pages and product screens into one template. Shared DNA is a strategic relationship, not a requirement that every artifact use the same layout.
